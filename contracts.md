# OCR query interaction

These are client interaction rules in the existing photo/OCR intake flow, not additional modules or server functions:

- The device camera and OCR remain in the Expo app (`expo-camera`, `expo-ocr-kit`); the photo URI is local to the device.
- After OCR, split the raw text into whitespace-delimited tokens, preserve their order, and initially leave every token unselected.
- Start the editable query empty; selecting tokens populates it.
- Join selected tokens with single spaces to populate the editable query input. The user can edit that field and must explicitly submit the resulting query to search.
- The lookup receives the exact submitted query; it does not infer a brand/model pair or silently rewrite the user's text.
- Display TryDiscs attribution alongside catalog results as required by the provider.

# REST API contracts

| Route | Method | Function mapping | Success result | How it fails | Spec rule it serves |
|---|---|---|---|---|---|
| `/bags/{user_id}/discs` | `GET` | `HomeBagView.render_home_bag(user_id)` with `UserSessionAndBagIdentity.get_active_user(user_id)` and `get_bag_id_for_user(user_id)` guard checks | Returns the bag list payload for the home screen. | No additional failure behavior is specified for the in-memory listing. | FR-003; home screen requirement. |
| `/bags/{user_id}/discs` | `POST` | `BagRepository.add_disc_to_bag(bag_id, disc_record)` after resolving `bag_id` via `UserSessionAndBagIdentity.get_bag_id_for_user(user_id)` | Returns the saved disc record, including its generated `disc_id`, after the user confirms the final add-disc form. | No additional failure behavior is specified for the in-memory write. | FR-001; Goal: add disc via photo and OCR; Scenario-001. |
| `/bags/{user_id}/discs/{disc_id}` | `PUT` | `BagRepository.update_disc_record(bag_id, disc_id, updated_fields)` after resolving `bag_id` via `UserSessionAndBagIdentity.get_bag_id_for_user(user_id)` | Returns the updated disc record and the user returns to the home bag view. | Returns `HTTP 404` if no disc with that ID exists in the user's bag. | FR-002; Scenario-002. |
| `/catalog/discs?q={query}` | `GET` | `TryDiscsCatalogLookup.find_candidate_matches(query)` | Returns `{"matches": [...], "attribution": "..."}` for the user to review and select. | Blank query returns HTTP 400; missing `TRYDISCS_API_KEY` returns HTTP 503; an upstream request or response failure returns HTTP 502. | Goal: add a disc via photo, OCR, and TryDiscs; Scenario-001. |
